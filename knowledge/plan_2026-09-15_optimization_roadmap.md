## 0. 一页摘要

本路线图的目标不是继续堆功能，而是把“汇课”从可运行原型推进为可长期自用、可安全升级、可维护扩展的多校课表 App。

建议总顺序：

1. 重新盘点工作区与知识库，消除事实冲突。
2. 先做本地备份/恢复，确保后续换签、换包名或重装不丢数据。
3. 完成整周 UI 与日期顺序改造（TASK-013），并建立可注入时间边界。
4. 固化正式 applicationId 与 Release 签名。
5. 把教学楼作息差异做成用户可维护能力，收口 TASK-012。
6. 优化学校切换、学期切换和历史学期管理。
7. 实现 Android 桌面小组件（TASK-002）。
8. 实现本地上课提醒（TASK-003）。
9. 增加课表健康检查、加载/错误状态和视觉回归。
10. 最后再做适配器安全更新、发布门禁和公开仓库清理。

本路线图不安排真实教务登录、适配器命中验证或差异预览实测；这些状态继续保持 UNVERIFIED/BLOCKED，不得因其它工作完成而改写为已验证。iOS 暂时不做，也不得顺手修改或宣称 iOS 可用。

## 8. OP-01 本地备份与恢复

### 目标

在无账号、无云同步的边界内，让用户可以在卸载、换包名、换签或换手机前保存本地数据。

### 备份内容

- 学校档案的非敏感字段。
- 学期。
- 手动与导入后的结构化课程。
- 基础作息和教学楼作息变体。
- 调休/停课例外。
- 当前学校、当前学期和外观偏好。

### 禁止内容

- 密码、Cookie、Session、Token。
- WebView 缓存和登录状态。
- 教务原始响应。
- 设备绝对路径和调试日志。

### 文件协议

- 使用版本化 JSON 或明确的单文件容器。
- 顶层至少包含 schemaVersion、appVersion、exportedAt、payload、checksum。
- exportedAt 只用于用户识别，不参与业务计算。
- checksum 用于检测文件损坏，不宣称防篡改。
- 未知新字段向前兼容；不支持的高版本必须拒绝并说明。

### 恢复策略

- 导入前只读预检，显示学校、学期、课程、作息和例外数量。
- 默认合并为新学校，禁止静默覆盖。
- 冲突时按稳定 ID 和内容指纹给出明确选项。
- 整次恢复必须事务化；任一关键步骤失败则不写入半套数据。
- 导入完成后重新计算 active school/semester，避免悬空设置。

### 验证

- 空库、单校、多校、多学期。
- 手动课与导入课同时存在。
- 作息变体与校历例外。
- 文件损坏、版本过高、字段缺失、重复导入。
- 导出文件敏感字段扫描为零命中。
- Android 文件选择器真实导出和恢复。

## 11. OP-04 教学楼作息变体编辑器

### 目标

把 TASK-012 从“不断硬编码学校楼栋”转为用户可维护的通用能力。

### 数据与规则

- 复用现有 ScheduleVariant 结构，除非证据证明无法表达。
- 每条规则包含名称、关键词集合和节次覆盖。
- 关键词匹配规则只有一处定义。
- 明确多规则同时命中时的优先级与冲突结果。
- 内置预设与用户自定义规则分层，更新预设不得覆盖用户修改。

### UI

- 规则列表显示名称、关键词摘要和覆盖节次数。
- 新增/编辑提供“输入教室名，预览命中结果”。
- 时间输入沿用 HH:mm 校验。
- 删除前显示影响，不删除课程本身。
- 规则为空时明确说明课程将使用基础作息。

### 验证

- 单关键词、多关键词、前缀教室文本。
- 无匹配、单匹配、多匹配冲突。
- 只覆盖部分节次。
- 老学校空变体修复与用户自定义并存。
- 课程详情、今日、整周、小组件/提醒消费结果一致。

## 12. OP-05 首页快速切换学校

### 目标

降低多校用户从首页切换学校的路径深度。

### 交互

- 点击 AppBar 学校名称打开轻量学校选择弹层。
- 当前学校显示勾选与当前学期摘要。
- 点选即切换；管理、编辑、删除仍进入学校管理页。
- 不在快捷弹层放危险删除操作。
- 切换后课程、学期、作息、例外和周次同时刷新。
- 切换失败时保留原学校并提示可操作错误。

### 验证

- 单校、多校、学校无学期、学校有多个学期。
- 快速连续切换。
- 切换后返回键、首页周次和设置身份卡一致。
- 48dp 触控、大字体、读屏顺序。

## 13. OP-06 学期生命周期与历史学期

### 目标

同一学校长期使用时不必删校重建，能创建新学期并回看历史课表。

### 要求

- 学校下可创建多个学期。
- 明确当前学期，每校独立保存。
- 历史学期默认只读回看，编辑需明确进入编辑状态。
- 新学期可复制基础作息与教学楼变体，但默认不复制课程和校历例外。
- 删除学期前显示课程、例外、通知和小组件影响。
- 删除必须事务化并修复 active semester 指针。

### 非目标

- 自动根据日期猜测并创建新学期。
- 从其它学校复制课程。
- 云端学期同步。

- 课程、学期、作息、学校、校历例外变化。
- 切换当前学校。

- 系统日期跨天和系统周期刷新。

### 验证

- 无课、单课、多课、调休、停课、学期前后。
- 小/中/大尺寸、日间/夜间。
- App 未运行时跨天。
- 删除当前学校后的空状态。
- 原生单测、Flutter 载荷测试、桌面真实添加和点击。

## 16. OP-09 课表健康检查

### 目标

在不自动改课的前提下，发现结构化课表中的可疑问题。

### 检查项

- 同周、同星期、节次重叠。
- 节次超出作息表。
- startSection 大于 endSection。
- 周次超出学期总周数。
- 显式时间起止倒置或格式非法。
- 教室命中多个作息变体。
- 调休目标星期缺失或越界。
- 课程缺时间且作息无法解析。

### 呈现

- 分为错误、警告、提示。
- 每条说明影响和可操作入口。
- 不显示内部适配器名称或原始响应。
- 不自动删除、合并或修改课程。

## 17. OP-10 加载、空与错误状态

### 目标

避免异步 provider 在加载或失败时被 `.value ?? []` 误显示为“无课”。

### 状态

- Loading：保留页面骨架，不闪烁“无课”。
- Empty：确认加载成功且确实为空。
- Error：显示简洁错误和重试入口。
- Stale：有旧内容时保留旧内容并提示刷新失败。

### 范围

- 首页学校/学期/课程流。
- 整周课表。
- 学校管理、学期设置、校历例外。
- 小组件同步状态只在设置或诊断区域呈现，不打扰首页。

## 18. OP-11 时间可测试性

### 目标

让周一、周日、学期前后、当前课程、跨日、小组件和提醒能够在测试中固定时间。

### 要求

- 统一提供设备“现在”的来源。
- 生产默认 DateTime.now，测试可注入。
- 日期归一化只有一处。
- 明确课程时间为学校所在地的墙上时间；暂不扩大到多时区同步。
- 页面不得在同一 build 中多次读取不同的 DateTime.now 导致跨分钟/跨日不一致。

### 当前并行改动

week_agenda.dart 已出现 today 参数，只能视为局部起点。接手 Agent需检查是否足以覆盖 UI、小组件和提醒；不得未经审查重复再建 nowProvider。

## 19. OP-12 视觉与无障碍回归

### Widget/Golden 场景

- 今日空课、单课、多课。
- 整周周中与周末。
- 调休、停课。
- 日间、夜间。
- 360dp、小型常规手机、平板约束。
- 1.0 与 1.3 倍文字。
- 长课程、长教室、长教师匿名数据。

### 要求

- Golden 固定时间、字体、像素比和主题。
- 不把平台阴影细微差异做成脆弱断言。
- 所有图标控件有可访问名称。
- Android 点击区域至少 48dp。
- 颜色不是状态的唯一载体。
- FAB、系统安全区和大字体互不遮挡。
- 视觉改动仍须模拟器实画，Golden 不替代人工检查。

## 20. OP-13 适配器安全更新（TASK-005）

### 目标

允许在不发整包的情况下更新适配脚本，同时保持来源可验证和失败可回退。

### 前置决策

- 远端索引托管位置。
- 索引签名或可信哈希策略。
- 最低/最高 App 版本兼容范围。
- 内置版本、缓存版本和远端版本的优先级。
- 更新失败和脚本执行失败的回退。

### 安全边界

- 只从固定 HTTPS 源拉取索引和脚本。
- 下载后先校验再启用。
- 更新不能修改 WebView 主机白名单或权限。
- 脚本仍只能通过既有桥契约返回结构化数据。
- 不上传页面内容、Cookie 或用户课表。
- 用户界面只显示“适配组件已更新/更新失败仍使用内置版本”，不暴露内部探测流程。

### 事实边界

即使更新通道全部测试通过，也不能据此宣称任何真实教务适配成功。

## 21. OP-14 发布门禁与仓库清理

### 发布检查脚本

脚本只检查并报告，不自动提交、推送或发布：

- git status 和 diff check。
- flutter analyze。
- flutter test。
- Android Release 构建。
- APK applicationId、version、debuggable、签名证书。
- Manifest 权限和网络安全配置。
- 敏感信息扫描。
- build 产物未被 Git 跟踪。
- THIRD_PARTY_NOTICES.md 存在且未被改写。
- 知识库版本、测试数字与实际一致。

### 清理候选

- tools/patch_*.py 一次性脚本。
- assets/icon/candidates/ 历史候选。
- 临时截图、UI dump、数据库副本。
- 未引用资源、过期 TODO 和失效注释。

删除前必须用 rg 和构建引用确认；不得批量递归删除不明确路径。

## 22. 每个工作包的统一实施流程

1. 用户明确批准具体工作包。
2. 调用适用 Skills。
3. 重新读取知识库、源码和当前 git diff。
4. 在 tasks.md 的 Now 登记范围、非范围和验证目标。
5. 建立或更新测试，先证明旧行为/缺陷。
6. 最小局部实现，不做顺手重构。
7. 只格式化修改文件。
8. 运行定向测试、analyze 和完整测试。
9. 需要 UI/平台行为时构建并实画。
10. 检查日志、敏感信息和模拟器残留。
11. 同步 current_state、tasks、design/architecture/testing/issues/changelog 中受影响部分。
12. 报告事实边界；只有全部 MUST 完成才关闭任务。

## 24. 停止与确认条件

出现以下情况必须停止并向用户确认：

- 需要确定最终 applicationId、备份冲突策略或提醒默认值。
- 需要覆盖、删除或迁移用户现有数据。
- 与未知并行改动发生重叠冲突。
- 需要新增权限、第三方依赖或联网服务。
- 需要真实教务凭据或真实课表数据。
- 工作自然扩展到 iOS。
- 需要提交、推送、创建 tag、release 或对外分发。

## 25. 推荐审批方式

用户无需一次批准整份路线图。建议按里程碑或单个 OP 编号授权，例如：

- “执行 OP-01 本地备份恢复。”
- “执行 Milestone A，但暂不做 OP-10。”
- “只做 TASK-013，不做其它优化。”

没有明确批准的工作包保持 PROPOSED，不进入代码。
